## The footer rule — this cost 13 episodes tonight, read it

**LeRobot commits the parquet footer when the recording run ends, not per
episode.** Every `✓ SAVED episode N` you see is not yet durable. If the run dies
uncleanly, the data parquet has no footer and the *entire dataset* is
unreadable — not just the last episode.

Confirmed by the datasets themselves:

```
medbottle_pick_CRASHED_NO_FOOTER    2 ep   BROKEN     (named for it)
glassbottle_pick_v2                13 ep   BROKEN     (tonight)
bottle_pickplace_OLD_BROKEN_BOTTLE 12 ep   OK
medbottle_pick_RETIRED_GRIP45       3 ep   OK
medbottle_pick_DEFORMS_GRIP60       2 ep   OK
glassbottle_pick                   20 ep   OK
```

Every dataset from a run that finished has `PAR1`. Both that died mid-run do not.

**Ctrl-C is clean.** Verified directly: a batch interrupted with Ctrl-C
finalised with a valid footer and 4 episodes intact. `KeyboardInterrupt` lets
the cleanup path run. What destroys a dataset is an *unclean* stop where no code
executes — a kernel hang or a power cut.

**So: record in batches of 5.** A hang then costs one batch.

```bash
# batch 1 — creates
... record_kinesthetic.py --repo-id local/NAME --episodes 5 ...
# batches 2,3,4 — note --episodes is the RUNNING TOTAL, not the increment
... --episodes 10 --resume ...
... --episodes 15 --resume ...
... --episodes 20 --resume ...
```

`--episodes 5 --resume` against 5 existing episodes exits immediately without
recording: `kept = dataset.meta.total_episodes` and the loop is
`while kept < args.episodes` (`record_kinesthetic.py:423`). It is a no-op, not
an error, and it looks like a crash if you are not expecting it.

**`--resume` writes a new file, not a rewrite.** Batch N lands in
`data/chunk-000/file-00N.parquet`. Committed batches are therefore immutable —
a later crash cannot corrupt them. This is better than it needed to be.

Check any dataset in seconds:

```bash
tail -c 4 <dataset>/data/chunk-000/file-000.parquet | xxd -p   # must be 50415231
```

## Camera — a measurement trap worth not repeating

RealSense auto-exposure needs **~60 frames (2 s)** to converge. A grab that
waits 15 frames reports roughly half the true brightness:

```
after  15 frames   mean 37.5
after  60 frames   mean 71.9
after 120 frames   mean 71.9
```

Several minutes were lost tonight to "the scene is too dark", which was the
measurement, not the room. lerobot's `connect()` does `sleep(1)` plus
`warmup_s=1` of reads — about 2 s of streaming — which is sufficient: measured
take-1 mean 70.6 against a settled 72.7, a gap of 2.1. **No change needed to
`warmup_s`.** Episode 1 is not darker than episode 20.
